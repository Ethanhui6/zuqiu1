# 绿茵浮沉 V18.2 UI/UX 实施与验收报告

版本：`18.2.0`  
构建：`2026-08-03.6`  
改造范围：仅界面、交互、信息层级与移动端稳定性；没有增加新的玩法系统。

## 1. 实际修改结果

### 1.1 手机端点击与遮挡

- 所有 `button`、图标按钮、选择卡、事件选项、球队卡和底部导航均使用不小于 `44×44px` 的触控区域。
- 修复了 320px 宽度下顶部返回按钮和主页按钮被响应式规则压缩为 42px 的问题。
- 点击反馈统一为 `scale(0.96)`，并由 `pointerdown / pointerup / pointercancel` 管理按压状态。
- 页面滚动容器固定为 `.page-container`，底部导航和顶部导航不参与正文滚动，避免被内容覆盖。
- 修复应用根节点在存档选择、创建球员和正式游戏之间切换时残留旧 class，造成遮挡或事件命中异常的问题。
- 主页面保留同一路由的滚动位置，局部状态更新不再强制回到顶部。

### 1.2 弹窗与底部 Sheet

`src/components/sheet.js` 已重写：

- 使用 `window.visualViewport.height` 计算可用高度。
- 正文区独立滚动，页脚操作区固定在 Sheet 内。
- 支持 `safe-area-inset-top / bottom`。
- 打开时锁定背景滚动，关闭后恢复原状态。
- 关闭后将焦点还给打开弹窗前的控件。
- 支持点击遮罩关闭和 Esc 关闭。
- 320×568 视口中，长内容可滚动，底部确认按钮保持在可操作范围内。

### 1.3 视觉层级与主题

- 默认背景为 `#F5F5F7`，主卡片使用白色/半透明白和克制阴影。
- 深色模式主背景改为 `#101114`，不再使用纯黑后台式页面。
- 非生涯首页固定显示“← 生涯首页”和主页按钮，浅色与深色模式均可见。
- 卡片圆角、按钮圆角、标题字号、正文颜色、间距和阴影统一由公共样式控制。
- 支持浅色、深色和跟随系统，现有主题持久化逻辑保持不变。

### 1.4 信息密度

- 生涯主页只保留潜力、体能、士气、教练信任等核心状态，其余内容通过“查看更多状态”展开。
- 转会报价默认只展示工资、年限、定位、签字费四项核心内容，解约金、奖金、出场承诺和发展计划折叠显示。
- 页面标题说明缩短，不再连续重复同一语义。
- 世界球队列表每页 18 支，不一次渲染全部球队。

### 1.5 天赋球探报告

新增并实际接入 `src/components/talentCard.js`：

- 普通、优秀、稀有、精英、传奇、隐藏六种视觉主题。
- 显示稀有度、星级、潜力区间、成长效率、主要优势、潜在风险和球探评价。
- 整张天赋卡均可点击，并使用 `aria-pressed` 表示当前选择。
- 天赋卡直接使用创建球员流程中的真实天赋、位置、风格和初始属性数据，不是独立静态展示页。

### 1.6 六边形能力图

`src/components/radarChart.js` 已重写：

- 普通球员和门将使用两套中文标签。
- 数据来自当前球员或创建流程当前选择的位置预览。
- ST、CB、GK 等位置生成不同能力轮廓。
- 显示数值节点、综合等级、位置色彩和无障碍描述。
- 属性点和多边形使用 CSS 过渡，在数据改变时平滑更新。
- 综合能力继续调用位置权重算法，不使用简单平均值。

### 1.7 球队展示

新增并实际接入 `src/components/clubCard.js`：

- 根据球队 ID 稳定生成识别色和文字队徽，不使用未授权图片。
- 青年队邀请显示球队、国家、联赛、梯队、青训星级、风格、年轻机会、位置适配、周薪和发展评级。
- 世界球队卡显示青训、年轻机会、球队风格、工资水平和球员位置适配。
- 这些卡片读取当前俱乐部数据库和当前球员位置，不是手写的演示球队。

### 1.8 事件与比赛选择

新增并实际接入 `src/components/eventCard.js`：

- 事件显示标题、两句以内场景摘要、分类、压力和选择数量。
- 过长背景折叠至“查看完整情境”。
- 每个选择是整张可点击卡片，显示图标、行动、简短后果、风险和收益类型。
- 选择继续调用原事件状态机，结果写入事件记忆和存档。
- 比赛关键选择使用相同视觉规范，但继续调用真实比赛结算逻辑。

### 1.9 创建流程步骤条

- 五个步骤显示名称、当前状态和完成勾选。
- 位置步骤直接显示动态六边形预览和位置职责。
- 天赋步骤使用球探报告卡。
- 青训步骤使用球队游戏卡。
- 底部上一页/下一页操作区在小屏幕中保持可点击。

## 4. 已知测试边界

当前运行环境禁止浏览器直接导航访问本地 HTTP 网站，因此不能声称已经在实体 iPhone、iOS Safari、Android Chrome 或真实地址栏伸缩场景中完成设备测试。

本次移动端验证使用系统 Chromium、项目实际 CSS、代表性组件 DOM 和真实视口尺寸执行几何、滚动和点击审计。部署后仍应在至少一台实体 iPhone 和一台 Android 手机上做最终手工验收。

## 5. 结论

V18.2 没有增加新玩法。现有创建球员、天赋、球队、事件、比赛、转会和存档逻辑保持连接；本次完成的是对这些真实系统的移动端交互、组件层级、信息密度、视觉反馈和主题体验重构。
