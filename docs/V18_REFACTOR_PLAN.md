# V18 重构计划与代码审计

## 1. 当前文件结构

原项目为无需构建工具的原生 HTML/CSS/JavaScript PWA。入口为 `index.html`，主游戏逻辑主要位于根目录 `app.js`，同时保留了一套未被入口使用的 `js/` 模块。数据位于 `data/`，包括 500 家俱乐部、500 个成长模板、330 项成就和多个分类事件文件。图片资源位于 `assets/`。

## 2. 现有功能

- 多步骤创建球员和球场位置选择基础版本
- 球员卡和六边形能力图
- 青训开局、赛季模拟、成长、伤病、国家队和荣誉基础逻辑
- 分类事件库和概率动画
- 500 家俱乐部、500 个模板、330 项成就数据
- 本地单存档和基础 PWA 文件

## 3. 严重 Bug

- 根 `app.js` 仍直接使用 `Math.random()` 处理天赋、成长特质、伤病和荣誉等重要结果。
- 旧 Service Worker 会主动注销自身，离线不可用，版本更新流程不可控。
- `index.html` 每次启动清空全部缓存，导致 PWA 失去意义。
- 根 `app.js` 与 `js/` 下另一套控制器并存，存在重复代码和维护歧义。
- 转会存在自动修改俱乐部的路径，缺少完整谈判状态和稳定报价。
- 部分事件数据固定为五个选项，显示结构重复。
- 页面大量使用整段 `innerHTML` 重建，滚动位置和监听器容易丢失。
- 版本、缓存名、存档版本和文档中的版本号不完全一致。

## 4. 数据结构问题

- 俱乐部身份字段与模拟评级字段没有明确区分。
- 500 个传奇模板全部标记为“传奇模板”，缺少普通、优秀、精英、传奇四级概率层。
- 成就数据部分为索引型条件，缺少统一判定表达式。
- 事件文件存在两代 Schema，需要统一规范化读取。
- 旧存档字段较扁平，缺少关系、粉丝分层、合同谈判和确定性随机状态。

## 5. UI 问题

- 信息密度高但层级不稳定，部分页面仍像网页仪表盘。
- 底部导航只有四项，未覆盖比赛、训练、转会等核心循环。
- 卡片、Sheet、按钮和状态条的视觉规则不完全统一。
- 中英文标签混用，英文缩写缺少中文辅助。

## 6. 移动端问题

- 通过整页重建会造成点击后闪动、滚动跳动。
- 弹窗背景锁定和安全区域处理不统一。
- 500 家球队和 330 项成就存在一次性渲染风险。
- 部分触控按钮小于 44px。

## 7. 存档兼容风险

- 原存档键为 `green-pitch-career-v18`，只有一个槽位且没有校验。
- 旧字段名称与新结构差异较大。
- 旧存档没有随机序列状态，迁移后需要生成稳定种子并保留原核心数据。

## 8. V18 重构文件列表

- `src/app/`：应用启动、路由、状态管理和配置
- `src/services/`：确定性随机、数据仓库、存档、多槽位、迁移、本地化
- `src/systems/`：生涯、比赛、训练、转会、事件、成就、关系、粉丝和结局
- `src/components/`：球员卡、雷达图、底部 Sheet、Toast、导航和通用 UI
- `src/pages/`：生涯、比赛、训练、转会、世界、我的和创建球员
- `src/styles/`：主题、基础、组件和页面样式
- `docs/`：计划、数据来源、迁移、测试、部署和更新记录

## 9. 实施顺序

1. 建立统一配置、状态、随机、存档和迁移。
2. 替换 Service Worker 和入口文件。
3. 建立浅色优先、深色和跟随系统主题。
4. 重做六页底部导航和可复用组件。
5. 重做创建球员、球场选位、风格、天赋和青训邀请。
6. 接入训练、比赛、事件、转会、粉丝、关系和成就。
7. 接入 500 家球队、500 个模板、330 项成就和事件库懒加载。
8. 执行自动化数据检查、浏览器流程测试和部署检查。

## 10. 验收标准

- 可直接静态部署，无构建步骤。
- 新建球员、保存、刷新、继续、导入导出均可用。
- 重大随机结果由统一 PRNG 产生并保存。
- 事件显示 2–5 个不同选项，并具有冷却和记忆。
- 转会必须由玩家确认，支持拒绝、暂缓和谈判。
- 500 家球队搜索采用分页，不一次性渲染全部详情。
- 默认浅色，主题选择持久化。
- iPhone 安全区域、触控尺寸和减少动画设置有效。
- Service Worker 可离线进入，并能提示新版本。

## 实施结果（2026-08-03）

上述计划已经落地为新的 `src/` 模块结构。旧入口未继续参与运行；新入口为 `src/main.js`。已完成统一状态、确定性随机、多槽存档、迁移、事件记忆、比赛、训练、转会、关系、粉丝、成就、赛季荣誉、结局与版本化 Service Worker。自动化测试结果见 `docs/V18_TEST_REPORT.md`。
