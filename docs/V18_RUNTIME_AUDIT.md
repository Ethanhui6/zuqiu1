# V18.1 运行审计与修复记录

审计日期：2026-08-03  
审计版本：18.1.0  
审计对象：实际部署入口 `index.html` → `src/main.js`，以及 `src/`、`data/`、`sw.js`、存档和测试代码。

## 审计结论

本轮没有把“入口存在”当作“功能完成”。审计按以下标准逐项执行：功能必须修改真实存档状态、可以从界面操作、具有失败或边界路径，并由自动化测试验证。

## 1. 拥有真实状态和数据逻辑的功能

以下系统会读取和修改当前存档，并同步写入本地存储：

- 创建球员：身份、位置、风格、有限天赋重抽、青年队邀请。
- 生涯推进：阶段、赛季、年龄、梯队、球队角色、合同和职业历史。
- 训练：训练计划、能力经验、疲劳、体能和伤病风险。
- 比赛：名单身份、关键选择、比分、时间线、评分、进球、助攻、零封、伤病和停赛。
- 事件：条件筛选、2—5项选择、确定性结果、即时后果、延迟后果、剧情链、冷却和事件记忆。
- 转会：夏冬窗口、稳定报价、接受、拒绝、暂缓、谈工资、谈定位、要求租借、谈解约金、主动意向和留队。
- 设施：青训基地、医疗中心、球迷商店、新闻发布厅和更衣室均会改变真实状态并写入访问历史。
- 粉丝与商业：本地、俱乐部、全球、社交关注、媒体热度、商业价值、舆论和增长历史。
- 关系：主教练、队友、队长、经纪人、管理层、球迷、媒体和国家队教练的多维关系。
- 荣誉、成就和结局：基于赛季及生涯纪录判定，不随机直接授予。
- 存档：三槽位、自动保存、手动保存、备份、导入、导出、校验、损坏恢复和旧档迁移。

## 2. 空入口审计

初始审计发现，俱乐部设施区中的青训基地、医疗中心、球迷商店、新闻发布厅和更衣室只具备展示层，未连接独立游戏逻辑。

已修复：

- 新增 `src/systems/facility/facilitySystem.js`。
- 每种设施拥有成功、失败、费用不足、阶段冷却等边界。
- 互动结果写入 `career.facilities`、`career.history`、随机状态及相关数值。
- 主球场、训练场、数据分析室和荣誉室分别连接比赛、训练、当前存档分析和成就页面。

复查后未发现仍然只显示“功能入口已添加”而没有动作的主要按钮。导航按钮只承担页面切换，不伪装成独立游戏系统。

## 3. 静态或模拟数据审计

玩家首页、比赛、训练、转会、成就、关系、粉丝和设施页面均从当前存档读取，不再使用固定演示数值。

仍属于静态资料或模拟数据的部分：

- 500家俱乐部的名称身份数据来自项目内置数据库。
- 球队实力、进攻、防守、财政、青训、球迷规模、城市、球场容量、战术和位置需求是游戏模拟评级，并在“世界”页面和数据说明中明确标注，不冒充官方或实时数据。
- 500条成长模板记录包含100个不同模板名称的五种成长变体；并非500位互不重复的真实球星。
- 事件内容是预制数据与运行时条件组合，不是联网实时新闻。
- 背景图和奖杯图仅为视觉素材，不参与结果计算。

## 4. `Math.random()` 审计

`src/`、入口文件、Service Worker和数据逻辑未发现 `Math.random()`。

重大结果统一使用可序列化的确定性随机系统：

- 天赋与青年队邀请
- 事件抽取和事件结果
- 比赛、伤病及关键节点
- 转会报价和谈判
- 设施结果

存档保存随机种子、当前状态和计数。同一存档、相同操作顺序会得到相同结果。

## 5. 英文界面审计

已清理明确的未翻译界面文字，包括 `Season Complete`、`Career Complete`、`Settings`、`Transfer Offer`、`Continue`、`Loading`、`Roguelike` 和 `B2B中场`。

界面保留的字母仅限：

- 俱乐部官方外文名作为搜索字段，不在主要卡片中强制展示。
- 程序内部位置代码和属性键，如 `ST`、`GK`、`pac`，不直接作为未翻译菜单文案。
- 版本号中的 `V18.1.0`。

用户可见的能力名称、位置、按钮、错误提示、转会和设置均为简体中文。

## 6. 转会功能审计

转会不是自动换队：

- `generateOffers()` 只生成并保存报价，不修改 `clubId`。
- 只有玩家点击“接受”后才改变俱乐部。
- “拒绝”保留原俱乐部并写入拒绝记录。
- “暂缓”只能使用一次，不能无限拖延。
- 谈判最多两轮，超过上限会失败。
- 报价过期后移入历史，不能继续接受。
- “留队争取位置”关闭本窗口报价，并在同窗口锁定，不能重复获取收益。
- 主动意向每阶段最多提交三家，并可能被拒绝、要求试训、仅提供租借或推迟。

## 7. 刷新一致性审计

- Store 更新改为同步写入存档，避免用户点击后立即刷新造成结果丢失。
- 已生成事件、比赛、比分、报价及随机状态保存在存档中。
- 同一报价、比赛和事件的自动测试在重新读取后保持一致。
- 损坏主存档会尝试恢复有效备份，并立即重新签名保存。

## 8. 事件重复审计

事件引擎现在记录：

- 已触发ID
- 最近标签
- 最近标题
- 最近选择结构
- 已选择方案
- 开启及关闭的剧情链
- 冷却时间和延迟后果

抽取时会排除不符合条件和冷却中的事件，避免最近12次重复标题，并禁止相邻事件重复选择结构。70次连续事件审计未出现最近12次内重复标题，也没有连续相同选择结构。

原始数据中的每条记录包含5个候选方案；运行时会根据存档状态确定性选出2—5个，玩家界面不再固定显示同样的五项。

## 9. 旧存档迁移审计

迁移层支持：

- 旧单存档键与多种历史键名探测
- V10/V11/V12/V17式扁平字段
- 早期V18缺失字段补齐
- 无校验旧档重新签名
- 损坏主档从备份恢复
- 无法恢复字段使用中性默认值，并在 `meta.migrationNotes` 中留下说明

导入文件会检查体积、JSON格式、校验和和可玩字段；损坏或伪造校验文件会被拒绝。

## 10. 手机滚动与交互审计

已修复代码层面的滚动跳动来源：

- 同页刷新保留 `.page-container.scrollTop`。
- 同页刷新不重新播放进场动画。
- 训练选择只更新相关卡片，不整页重建。
- Sheet打开时锁定背景滚动，关闭后恢复原状态。
- 世界和成就使用分页/分批加载。
- 支持安全区域、减少动画和移动端触控尺寸。

自动化测试已验证路由刷新保持滚动位置。由于执行环境的Chromium被组织策略禁止访问 `localhost`、私网IP和 `file:` 地址，无法完成真实浏览器截图回归；这一项没有被冒充为已完成，仍需部署后在实际iPhone或Android浏览器做最终手动确认。
